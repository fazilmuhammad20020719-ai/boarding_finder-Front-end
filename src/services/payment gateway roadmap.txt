# Payment Gateway Integration Roadmap (PayHere Sri Lanka)

To allow students to securely pay security deposits or rent, we will integrate **PayHere**, which supports local Visa/Mastercard, Dialog eZ Cash, mCash, and local bank transfers. 

This roadmap outlines the exact architectural changes required across our frontend, backend, and database to securely process transactions.

---

## 🛠️ Step 1: Account & Environment Setup
Before writing any code, we must set up the gateway infrastructure:
1. **Create Sandbox Account:** The Admin/Developer must create a free testing account at `sandbox.payhere.lk`.
2. **Retrieve Keys:** Obtain the `Merchant ID` and `Merchant Secret`.
3. **Environment Variables:** Add these keys to the backend `.env` file so the server can securely communicate with PayHere without exposing the secret to the frontend.

## 🗄️ Step 2: Database Changes (Backend)
We need to track where money is going and securely log transactions.
1. **New Table `payments`:**
   - `payment_id` (Primary Key)
   - `booking_id` (Foreign Key linked to the booking)
   - `payhere_order_id` (Unique reference generated by us)
   - `amount` & `currency` (LKR)
   - `status` (Enum: `pending`, `success`, `failed`, `canceled`)
   - `payment_method` (e.g., VISA, MASTER, EZCASH)
2. **Update `bookings` Table:**
   - Ensure the booking table has a status column (`pending_payment`, `confirmed`, `rejected`) so we know when a student has paid successfully.

## 💻 Step 3: Payment Checkout Flow (Frontend)
When a student clicks "Book Now" on a listing:
1. **Create Pending Booking:** The frontend (`PropertyDetails.jsx`) sends a request to our backend to create a `pending_payment` booking.
2. **Generate Payment Data:** The backend responds with the exact amount, a unique order ID, and the hashed `Merchant Secret`.
3. **Trigger PayHere Checkout:** The frontend dynamically generates a hidden HTML form containing the payment data and automatically submits it, redirecting the student to the secure PayHere payment page.

## 🔌 Step 4: Webhook & Security Verification (Backend)
This is the most critical security step. We cannot trust the frontend to tell us if a payment was successful (hackers can easily fake a "success" redirect).
1. **Create Webhook Endpoint (`/api/payments/notify`):**
   - PayHere will send an invisible server-to-server POST request to this endpoint the moment a payment succeeds or fails.
2. **Cryptographic Hash Verification:**
   - The backend will receive the data, hash the `Merchant Secret` along with the `Order ID` and `Amount` using MD5, and compare it to the signature sent by PayHere. 
   - *If they match*, we know the payment is 100% legitimate.
3. **Update Database:**
   - Update the `payments` table status to `success`.
   - Update the `bookings` table status to `confirmed`.

## 🌐 Step 5: User Redirection Pages (Frontend)
After the user finishes paying on PayHere, they are redirected back to our site.
1. **Create `PaymentSuccess.jsx`:** A page thanking the student, showing their booking receipt, and providing a button to return to their dashboard.
2. **Create `PaymentCancel.jsx`:** A page showing that the payment failed or was canceled, allowing them to try again.
